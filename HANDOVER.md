# Передача Broker CRM владельцу

Мини-апп работает на нескольких сервисах. Чтобы проект полностью принадлежал владельцу,
каждый из них должен быть на его аккаунте. Админ (разработчик) остаётся приглашённым
участником, и владелец может забрать у него доступ в любой момент.

Порядок важен: делайте по шагам и после каждого шага проверяйте, что всё работает
(см. «Проверка» в конце).

## 1. Код — GitHub

Сейчас: `github.com/vlkondratenko29-code/--crm`.

1. Владелец создаёт аккаунт GitHub (если его нет), лучше с 2FA.
2. Админ: репозиторий → **Settings → General → Danger Zone → Transfer ownership** → логин владельца.
3. Владелец принимает перевод (придёт письмо).
4. Владелец: **Settings → Collaborators** → добавляет админа, если хочет, чтобы тот продолжал дорабатывать CRM.

После переноса у репозитория сменится адрес. Render нужно переподключить к новому адресу (шаг 3).

## 2. База данных — Supabase

Здесь хранится всё: лиды, события, счета брокера, депозиты, ЗП, P&L.

1. Админ: Supabase → организация проекта → **Team** → пригласить владельца с ролью **Owner**.
2. Владелец принимает приглашение.
3. Владелец понижает админа до **Developer** или удаляет его.
4. Владелец включает 2FA и проверяет тариф и способ оплаты: на бесплатном тарифе проект
   засыпает после недели без запросов.

Строка подключения к базе (`DATABASE_URL`) находится в Supabase → Project Settings → Database.

## 3. Сервер — Render

Здесь работает API и сам мини-апп. При каждом деплое Render сам собирает фронтенд
(Dockerfile). Если сборка упадёт, продолжит работать прошлая версия.

1. Админ: Render → **Workspace settings → Members** → пригласить владельца, сделать **Owner**.
2. Если сервис привязан к репозиторию по старому адресу, после шага 1 обновить:
   сервис → **Settings → Build & Deploy → Repository**.
3. Владелец удаляет админа из workspace или оставляет как участника.

Альтернатива: владелец создаёт новый Web Service на своём аккаунте из репозитория
(Docker, Dockerfile `api/Dockerfile`) и переносит все переменные из таблицы ниже.
Потом в @BotFather нужно поменять адрес мини-аппа на новый.

### Переменные окружения (Render → Environment)

Значения храните в менеджере паролей, не пересылайте в чатах.

| Переменная | Что это | Где взять |
| --- | --- | --- |
| `DATABASE_URL` | Подключение к базе | Supabase → Project Settings → Database |
| `TELEGRAM_BOT_TOKEN` | Токен бота, без него API нельзя защитить | @BotFather → бот → API Token |
| `OWNER_USERNAMES` | Владельцы CRM через запятую: всегда админы, их нельзя отключить из мини-аппа | Telegram-логины без @, например `owner,jokwq` |
| `TELEGRAM_NOTIFY_CHAT_ID` | Чат или группа для уведомлений о FTD | id группы, куда добавлен бот |
| `NOTIFY_EVENTS` | О каких событиях уведомлять, по умолчанию `FTD` | — |
| `CHATTERFY_API_KEY` | Ключ API Chatterfy (может быть сохранён и во вкладке «Контроль») | Chatterfy → настройки пространства → API |
| `CHATTERFY_BOT_ID`, `CHATTERFY_SPACE_ID` | Бот и пространство Chatterfy | адрес бота в Chatterfy |
| `CHATTERFY_WEBHOOK_SECRET` | Секрет входящего вебхука `/webhook/chatterfy?secret=...` | придумать и вписать в Chatterfy |
| `CHATTERFY_WEBHOOK_URL` | Исходящий вебхук в Chatterfy | Chatterfy → Webhooks & API |
| `DATA_SINCE` | С какого дня CRM считает данные, по умолчанию `2026-10-09` | — |
| `FB_ACCESS_TOKEN`, `FB_AD_ACCOUNT_IDS` | Расход из Facebook сам, без CSV (токен с `ads_read`, id кабинетов через запятую) | Business Manager → Пользователи системы → Сгенерировать маркер |
| `DIGEST_HOUR` | Во сколько (время команды) приходит утренняя сводка, по умолчанию `9` | — |
| `SESSION_SECRET` | Необязательно: ключ подписи сессий сайта (по умолчанию берётся `TELEGRAM_BOT_TOKEN`) | любая длинная случайная строка |
| `GEO_DEFAULT` | ГЕО лидов, у которых вебхук без `geo`, по умолчанию `TR` | — |

## 4. Telegram-бот — @BotFather

1. Владельцу нужна включённая 2FA в Telegram.
2. Текущий владелец бота: @BotFather → `/mybots` → бот → **Bot Settings → Transfer Ownership** → выбрать владельца.
3. Токен после передачи не меняется. Если владелец сделает **Revoke token**, новый токен
   нужно сразу вписать в `TELEGRAM_BOT_TOKEN` на Render.

## 5. Chatterfy

1. Пространство и бот Chatterfy должны принадлежать владельцу, админ — участник.
2. Если ключ API выпускал админ, владелец выпускает новый и вписывает его в
   `CHATTERFY_API_KEY` (или во вкладку «Контроль» в мини-аппе), а старый отзывает.
3. В настройках вебхуков Chatterfy должен стоять адрес сервера Render + `/webhook/chatterfy?secret=...`.

## Новое ГЕО (свой бот в Chatterfy)

Под каждое ГЕО свой бот. Чтобы CRM разделяла их в P&L и когортах:

1. В новом боте настройте вебхук на тот же адрес CRM, но с параметром ГЕО:
   `https://<адрес-Render>/webhook/chatterfy?secret=...&geo=MX` (вместо `MX` код страны, например `CO`, `PE`).
   У турецкого бота параметр можно не ставить: лиды без `geo` считаются `TR`.
2. В мини-аппе: «Сверка» → «Регистрации и депозиты → Chatterfy» → для нового ГЕО вставьте ссылку
   Custom Postback **из его бота**. Иначе регистрации и депозиты этого ГЕО не уйдут в его бота.
3. «P&L» → «Внести» → «Тир по странам»: выставьте тир CPA для страны (по сетке FxPro).
4. Кампании Ads Manager и отчётов баеров относятся к ГЕО автоматически: к тому, откуда пришло
   большинство лидов кампании. Поэтому не смешивайте разные ГЕО в одной кампании.

Вкладка «Контроль» (проверка сообщений операторов) пока смотрит только основного бота (`CHATTERFY_BOT_ID`).

## CRM в браузере (отдельный сайт)

CRM открывается и как обычный сайт: `https://crm-g7f7.onrender.com` (адрес сервиса на Render).
Вход — логин и пароль. Логин — Telegram username человека, пароль генерирует только CRM.

Как выдать доступ:

1. Мини-апп или сайт → «Команда» → у человека кнопка **«Пароль для сайта»**.
2. CRM покажет логин и пароль **один раз** — скопируйте и отправьте человеку лично.
   Сам пароль нигде не хранится (только его хеш), увидеть его потом нельзя: потерял — **«Новый пароль»**.
3. Новый пароль сразу выкидывает человека со всех браузеров, где он входил со старым.
4. **«Закрыть сайт»** — убрать вход на сайт (мини-апп в Telegram остаётся). «Отключить» — убрать доступ совсем.

Первый пароль себе админ выдаёт так же — из мини-аппа в Telegram.
После 5 неверных паролей вход для этого логина блокируется на 15 минут. Сессия на сайте живёт 30 дней.
`SESSION_SECRET` на Render (необязательно) — ключ подписи сессий; если его поменять, все выйдут с сайта.

## 6. Владелец в самой CRM

1. На Render в `OWNER_USERNAMES` вписать Telegram-логин владельца.
2. Перезапустить сервис: владелец сразу станет админом, и его нельзя будет отключить из мини-аппа.
3. Остальных (админов, баеров, обработчиков) владелец сам добавляет и отключает во вкладке «Команда».

## Утренняя сводка в Telegram

Каждый день после 9:00 бот присылает админам: вчера (лиды, реги, FTD, трафик, доход CPA, ROI) и месяц
(доход, расход, прибыль, прогноз). Включить/выключить для себя и «Прислать сейчас» — вкладка «P&L».
Бот пишет только тем, кто хоть раз открывал мини-апп. Бесплатный Render засыпает без запросов —
тогда сводка придёт, как только сервер проснётся (обычно с первым лидом из Chatterfy).

## Расход из Facebook автоматически

1. business.facebook.com → Настройки компании → Пользователи → **Пользователи системы** → добавить (роль «Администратор»).
2. Назначить ему рекламные аккаунты (доступ «Просмотр результатов» достаточно).
3. «Сгенерировать маркер» → приложение компании → разрешение **ads_read** → срок «Никогда».
4. На Render: `FB_ACCESS_TOKEN` = маркер, `FB_AD_ACCOUNT_IDS` = id кабинетов через запятую (из Ads Manager, `act_…` или только цифры).
5. Перезапустить сервис. Дальше CRM сама раз в час забирает расход за последние 3 дня;
   «Статистика» → «Баинг» → «Обновить сейчас» / «За 30 дней».

Расход в P&L считается в долларах — кабинеты должны быть в USD.

## Что делать каждый месяц

- **1-го числа загрузить отчёт FxPro** (вкладка «Сверка»). Он закрывает прошлый месяц:
  по разнице между отчётами CRM видит передепы и считает CPA за месяц.
- **Внести IB** во вкладке «P&L → Внести»: «Доход → IB», количество лотов из IB-кабинета FxPro
  (CRM умножит на $16).
- **Внести расходы**, которые CRM не видит сама: CRM, накрутки, сервисы, аккаунты, ЗП команды.
- Если пришла фактическая выплата CPA, внести её как «Доход → CPA»: тогда за этот месяц
  в P&L будет факт вместо расчёта.

## Проверка после каждого шага

- Мини-апп открывается из Telegram, видна вкладка «Статистика».
- Новый лид из Chatterfy появляется во вкладке «Лиды».
- Вкладка «P&L» открывается у владельца.
- В Render → Logs нет ошибок подключения к базе.
